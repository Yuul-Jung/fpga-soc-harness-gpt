1. 프로젝트 목적

AMD/Xilinx, Intel/Altera, Lattice의 공개 FPGA 주변장치 및 종합설계 자료를 조사합니다. CPU 단독 설계보다 센서·계측·모터·로봇·영상·통신·보안 등 실제 SoC 주변장치 응용에 집중합니다.

자료 조사 → 출처·라이선스 추적 → 검토·개선 → Design IR(설계 중간표현) → RTL·소프트웨어·구조도·HTML 생성 → 자동 검증 → 게시·이력 축적

최종 산출물은 전체 메인 HTML, 캡스톤별 독립 HTML, 구조화 디지털 계통도, 신호 연결표, 실제 실행 가능한 RTL 및 소프트웨어, 테스트벤치, BOM(부품 목록), 검증 기록입니다.

3. GitHub Actions의 1h / 90m / 150m 자동 실행

주기단계수행 내용한국 시간
1시간research새로운 FPGA 응용 공개자료 검색, 저장소 중복 제거 및 출처 추적, 기존 HTML·SVG·소스 회귀검증매시 07분
90분review전체 수집 자료의 메타데이터·라이선스·증거 재검토, 제안 개선, 기존 제작 자료 재검증09:17, 11:17, 13:17…
150분factory검증 게이트를 통과한 내부 템플릿으로 과제화, 전체 HTML·구조도·테스트벤치 검증 및 갱신09:27, 13:27, 17:27…
# UTC cron
7 * * * *       # 매시간 조사
17 */2 * * *    # 90분마다 검토
27 */4 * * *    # 150분마다 캡스톤 과제화

중앙 실행 파일은 continuous-pipeline.yml입니다. GitHub Actions 예약 실행은 지연되거나 누락될 수 있으므로 정확한 시간에 실행됨을 보장하지 않습니다.

핵심 구분: 150분마다 반드시 새로운 과제가 완성되는 것은 아닙니다. 재사용 가능한 원본 RTL 템플릿과 검증된 설계 근거가 있을 때만 신규 과제를 생성합니다. 검색 방식은 회전형 Python 휴리스틱이며, 매시간 LLM이 자율적으로 코드를 작성하는 에이전트는 아닙니다.

4. 구현 완료와 미구현 사항의 구별

현재 구현한 기능

  • 공개 GitHub 저장소 메타데이터, HDL 파일 트리, 라이선스 및 소스 트리 SHA 조사
  • 제조사·보드·응용·검증 관점 회전 검색 및 기존 목록의 축적
  • 초기 공개 프로젝트 11건에 대한 참고 목록과 설계 구상 페이지
  • Design IR(JSON) 기반 HTML·SVG·연결정보·BOM·자체 소스 및 ZIP 생성
  • 메인 HTML, 캡스톤 목차 및 과제별 상세 HTML을 연결한 자료실
  • 자체 RTL 시뮬레이션, C 자체 테스트, 기존 HTML 링크·구조도·해시 회귀검증
  • smart_fan 독립 RTL·테스트벤치·C 샘플 및 pulse_event_meter 내부 템플릿

아직 완료하지 않은 기능

  • 제3자 저장소 RTL을 일괄 해석하고 자동으로 Basys3/MicroBlaze V에 포팅하는 AI 에이전트
  • 모든 후보에 대한 Vivado/Quartus/Radiant 실제 합성 및 타이밍 결과
  • MicroBlaze V, AXI Block Design, XDC, 주소맵, Vitis 프로그램을 결합한 보드 재현 프로젝트
  • KiCad 전기 계통도·넷리스트 생성과 ERC(전기 규칙 검사)
  • 모터·센서 실물 배선 및 Basys3 보드 정상 동작 입증
  • 정식 GitHub Pages 게시: 인계서 작성 당시 배포 작업이 건너뛰어진 상태여서 별도 활성화 확인 필요
확인된 정식 캡스톤 원본은 인계 당시 capstones/smart_fan 1건입니다. instrument_pulse_counter는 검토 조건을 만족할 때 생성할 수 있는 템플릿입니다. 이후 실제 등록 여부는 최신 GitHub 트리를 확인해야 합니다.

5. Claude 독립 개발·RTL 설계 원칙

  1. 폴더 및 저장소 분리: Claude 전용 로컬 폴더와 독립 Git 저장소에서 개발하고 ChatGPT 저장소에 직접 push하지 않습니다.
  2. 검증 우선: 정상 코드를 경쟁 목적으로 재작성하지 않습니다. 실제 오류·선택적 개선·향후 확장을 명확하게 구분합니다.
  3. Shell/Wrapper Top: Top Module에는 보드 핀과 상수·단순 배선 및 모듈 인스턴스만 배치하고 기능 정책은 Controller/IP에 구현합니다.
  4. 주 대상: Basys3 + MicroBlaze V SoC, AXI4-Lite 기반 Register Map 및 재사용 가능한 RTL 주변장치입니다.
  5. 다중 제조사: Intel Avalon, Lattice 및 AMD AXI 주변장치 이식은 업체별 어댑터를 구분합니다.
  6. 저렴한 범용 부품: Digilent 전용 Pmod를 필수 조건으로 삼지 않고 Arduino 호환 센서·액추에이터를 우선 검토합니다.
  7. 전기 안전: Basys3 디지털 I/O의 3.3V 기준을 준수하고 5V·12V 및 모터·릴레이 코일을 FPGA 핀에 직접 연결하지 않습니다.
  8. 명칭 일치: 코드와 다이어그램의 모듈명·포트명·Clock·Reset·비트 폭이 일치해야 합니다.
  9. 라이선스: 출처·SPDX·의존성·사진 권리를 검토하지 않은 외부 RTL/그림을 무단 재배포하지 않습니다.
  10. 증거 기반 발표: Simulation → Synthesis → Implementation → Timing → Board Test를 구분하고 미실시를 성공으로 표시하지 않습니다.
  11. 누적 재검증: 1h·2h·4h 각 실행마다 기존 모든 자료도 확인하되, 승인된 원본 RTL·XDC는 자동 덮어쓰지 않습니다.

7. 참고용 원본 복제 및 검증 명령

ChatGPT 저장소는 참고 폴더에 복제하고 Claude 프로젝트는 별도 폴더에 생성합니다.

# 공개 ChatGPT 참고 저장소를 분석 전용으로 복제
git clone --depth 1 https://github.com/Yuul-Jung/fpga-soc-harness-gpt.git ~/fpga-soc-harness-gpt-reference

# 독립 Claude 작업 폴더 생성
mkdir -p ~/fpga-soc-harness-claude
cd ~/fpga-soc-harness-claude
git init -b main

Ubuntu에서 참고 하네스 테스트

# 필요한 도구 설치
sudo apt update
sudo apt install -y python3 iverilog gcc

# 반드시 참고 폴더에서 실행
cd ~/fpga-soc-harness-gpt-reference

python3 -m unittest discover -s tests -v
python3 -m harness.review --offline
python3 -m harness.refine
python3 -m harness.factory
python3 -m harness.maintenance --stage factory

# 메인/캡스톤별 HTML 열람
python3 -m http.server 8000 --directory site

로컬 서버가 실행 중일 때 http://localhost:8000/을 방문합니다. 원본 참고 폴더에서 수행하는 factory 명령은 조건에 따라 새 과제 폴더를 만들 수 있으므로, 보존이 필요하면 사본에서 실행합니다.

8. Claude의 첫 작업 지시

  1. GitHub의 main 파일을 읽고 본 인계서의 구조·구현 상태와 일치하는지 확인합니다.
  2. Python, GitHub Actions, HTML 생성기의 실제 오류·보안·유지보수성을 검증하되 가짜 결함이나 불필요한 기능 변경을 만들지 않습니다.
  3. Claude 전용 하네스의 독립 폴더·저장소 및 1h·2h·4h 자동화를 설계하고 기존 자료 누적 검증을 구현합니다.
  4. 메인 HTML과 과제별 HTML을 사용자가 클릭해 열람할 수 있도록 구성합니다.
  5. 원본 공개 프로젝트의 실제 소스·포트·Clock·Reset·데이터폭을 분석하는 기능을 추가하되 라이선스와 실행 검증을 분리합니다.
  6. 각 과제에서 전기적 연결과 디지털 구조도를 구분하고, 소스·테스트벤치·검증 증빙을 함께 제공합니다.
  7. 수집 품질·재현성·회로 정확성·캡스톤 완성도·HTML 접근성을 공통 평가 축으로 삼되 상대 하네스의 정상 코드를 고의로 트집잡지 않습니다.
최종 목표: 두 하네스를 서로 다른 폴더·저장소에서 독립 발전시키면서 같은 기준으로 평가합니다. 자료 수집만 자동화하는 것이 아니라 재현 가능한 FPGA SoC 캡스톤의 HTML 교재·구조도·전기 계통도·실행소스·검증 기록까지 체계적으로 축적합니다.
